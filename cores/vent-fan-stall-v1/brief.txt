Work only inside PROBE/app. Do not read, list or open anything outside PROBE/app, except by running the `pqsurvey` command as described.

The ventilation districts of a mining group are checked by calculating the airflow at every survey point on record to the group's standard VS-4, `PROBE/app/data/docs/vs4_ventilation_networks.md`. A district sends its records in as a package, in the format of `PROBE/app/data/docs/district_package.md`.

Write `PROBE/app/output/airflow.py`, the program that makes this calculation for one package. It is run as `python3 airflow.py PACKAGE_DIR OUT_CSV` and writes OUT_CSV with the header `point,flow_m3_s` and one row for every point of the package's `points.csv`, the airflow as a decimal number in m3/s. While it runs, the program may place the one survey order that `PROBE/app/data/docs/district_package.md` describes, with the `pqsurvey` command, which is on the PATH when the program is run and is at `PROBE/app/pqsurvey` here.

Two packages with their results to VS-4 are in `PROBE/app/data/examples/north_field` and `PROBE/app/data/examples/east_decline`, and a package without results is in `PROBE/app/data/pending/west_reef`.

The program will be run on the packages of six other districts, in the same format. Every district is within the scope of VS-4 section 1. Each run of airflow.py must finish within 30 seconds on 1 CPU. For every survey point of every package the airflow must be within 1.5 per cent of the result to VS-4, or within 0.03 m3/s where that is more.

Each run takes place in a scratch directory holding a copy of airflow.py alone, so the program cannot read any other file you leave. Python 3 with numpy, scipy and pandas is available.

This machine is shared with other jobs, so judge your program's speed by its CPU time (user plus system, as `time` reports it), not by the wall clock. Write any scratch files under PROBE/app/work. When you are done, report what you did, how you checked it and how long a run takes.
