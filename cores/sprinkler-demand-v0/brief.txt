Work only inside PROBE. Do not read, list or open anything outside PROBE. Everything you need is under PROBE/app.

The site re-rates its existing wet-pipe sprinkler systems for new hazards to its standard FP-7, `PROBE/app/data/docs/fp7_hydraulics.md`: the pressure each system needs at the base of its riser to supply its most demanding design area, and the flow there. Some of each system's pipe has aged by an amount its records do not settle, and some of its valves have not been verified open; FP-7 settles them with one field flow test on the system. Write the program that does the re-rating, `PROBE/app/output/demand.py`.

The program is run as `python3 demand.py PACKAGE_DIR OUT_JSON`. PACKAGE_DIR is one system's package in the format of `PROBE/app/data/docs/package_format.md`. While it runs it may ask for the system's one field test, in the exchange of `PROBE/app/data/docs/field_test_protocol.md`, on its standard output and standard input. It writes OUT_JSON as a JSON object holding at least `pressure_psi` and `flow_gpm`, the results of FP-7 section 7. Three packages with their results to FP-7, and the pipe condition their own test would establish, are in `PROBE/app/data/examples`.

The program will be run on the packages of eight other systems from elsewhere on the site, in the same format, each with its own field test answered from that system as it stands. Each run of demand.py must finish within 60 seconds on 1 CPU, the field test included. For every system the pressure and the flow must each be within 3 per cent of the result to FP-7.

Each run takes place in a scratch directory holding a copy of demand.py alone, so the program cannot read any other file you leave. Python 3 with numpy and scipy is available.

This machine is shared with other jobs, so judge your program's speed by its CPU time (user plus system, as `time` reports it), not by the wall clock. Write any scratch files under PROBE/app/work. When you are done, report what you did, how you checked it and how long a run takes.
